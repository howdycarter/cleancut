TheSwiftKit – Product Documentation

A complete guide to configuring, customizing, and shipping your SwiftUI app.

1. Introduction

TheSwiftKit is a production-ready SwiftUI template that bundles onboarding, authentication, paywalls, analytics, notifications, AI assistants, settings, and local persistence into a modular, configurable project. This documentation walks you through setup, provider integrations, customization, and maintenance so you can launch rapidly with confidence.

Scope: This HTML bundle is designed for offline delivery. All links reference in-project files or external services you will configure separately.

3. Feature Overview

The template ships with modular, opt-in features that work independently. You can remove or extend them without affecting the rest of the project.

  • Onboarding: Carousel-style introduction with multiple layout presets.
  • Authentication: Email/password via Supabase with profile capture and local fallback.
  • Paywall & Subscriptions: RevenueCat-powered offerings with StoreKit previews.
  • Analytics: TelemetryDeck signals with no-op fallback when keys are missing.
  • Notifications: Unified service for local scheduling and APNs token management.
  • AI Wrappers: Chat, image, and vision endpoints backed by a Flask OpenAI proxy.
  • Settings Module: Appearance toggles, account actions, and debug utilities.
  • Local Persistence Demo: Core Data stack showcasing CRUD patterns.

4. Requirements

  • Xcode 15 or newer with Swift 5.9+.
  • iOS 16.0 minimum deployment target.
  • Service accounts as needed: Supabase, RevenueCat, TelemetryDeck, OpenAI (optional for AI), Apple Developer Program.
  • Optional tooling: Supabase CLI for Edge Functions, Python 3.10+ for the AI backend.

6. Setup & Installation

6.1 Clone & Open

  1. Clone or download the repository to your Mac.
  2. Open TheSwiftKit.xcodeproj in Xcode 15+.

6.2 Create Secrets File

  1. Duplicate Config/Secrets.sample.swift to Config/Secrets.swift.
  2. Fill in your API keys and URLs (details in Configuration & Secrets).

6.3 Configure App Identity

  • App name: update appName in Config/AppConfig.swift.
  • Bundle ID: edit PRODUCT_BUNDLE_IDENTIFIER inside project.yml (or via Xcode → Targets → Signing).
  • Brand colors: update primaryColorHex and accentColorHex in Core/Theme/DesignTokens.swift or via AppConfig.Branding.

6.4 Assets & Icons

  • Replace app icon images in Resources/Assets.xcassets/AppIcon.appiconset.
  • Optionally add an AppLogo image set used across onboarding and paywall screens.

6.5 Build & Run

With secrets configured, build and run the project on the iOS Simulator or a device. Missing keys fall back to safe no-op implementations so the UI remains interactive.

7. Configuration & Secrets

7.1 App Configuration (Config/AppConfig.swift)

  • appName: Replaces __APP_NAME__ tokens in UI copy.
  • bundleId: Displayed for reference; actual identifier controlled in build settings.
  • backend: .supabase or .local, toggles repository implementations.
  • layout: Example layout toggle (.list or .grid) consumed by demo views.
  • onboardingStyle: Choose .carousel, .highlights, or .minimal.
  • branding: Set primary/accent colors once for global theming.
  • featureFlags: Enable/disable modules (onboarding, auth, paywall, notifications).
  • legal: Provide live URLs for Privacy Policy and Terms.

7.2 Secrets (Config/Secrets.swift)

Populate the following constants (they are read at runtime by dependency injection).

Key Where to obtain Used by
supabaseURL Supabase Project Settings → API → Project URL Supabase Auth/Profile/Subscriptions repositories
supabaseAnonKey Supabase Project Settings → API → anon public key Supabase client initialization
telemetryDeckAppID TelemetryDeck Dashboard → Destination App ID Analytics service
revenueCatAPIKey RevenueCat Dashboard → Project → API Keys → Public SDK Key (iOS) Purchases service (RevenueCat)
aiBackendBaseURLString Your AI backend origin (local Flask: http://127.0.0.1:5001) AI chat/image/vision views
accountDeletionURLString Your hosted account deletion request endpoint (optional) Settings → Account deletion
Sign in with Apple fields Apple Developer → Identifiers → Services IDs & Keys Future Sign in with Apple integration (disabled by default)
Never commit real credentials. Use encrypted secrets in CI/CD or environment-specific Secrets.swift files ignored by version control.

7.3 Feature Flags (Config/FeatureFlags.swift)

Toggle entire modules on/off (e.g., disable onboarding once users are live). The DI container reads these flags to decide which flows to present.

8. Supabase (Authentication & Database)

8.1 Create a Supabase Project

  1. Sign in at supabase.com and create a new project.
  2. Copy the Project URL and anon key into Secrets.swift.

8.2 Enable Email Authentication

  1. Supabase Dashboard → Authentication → Providers.
  2. Enable Email/Password and configure SMTP if you plan to send confirmation emails (for development, disable confirmations).

8.3 Profiles Table

The Swift app expects a profiles table to store user metadata (name, handle, avatar URL). Create via SQL:

create table public.profiles (
  id uuid references auth.users primary key,
  full_name text,
  bio text,
  avatar_url text,
  updated_at timestamptz default now()
);
alter table public.profiles enable row level security;
create policy "Profiles are viewable by owners" on public.profiles
  for select using (auth.uid() = id);
create policy "Profiles are updatable by owners" on public.profiles
  for update using (auth.uid() = id);

Update columns to match your desired profile schema. The default repository writes full_name, bio, and avatar_url.

8.4 Storage for Avatars

  1. Storage → Create bucket avatars.
  2. Policies: allow authenticated users to SELECT and INSERT. Optionally allow public read for avatars.

8.5 Subscriptions Mirror

  1. Run the SQL migrations in Backend/Supabase/sql in order:
psql < Backend/Supabase/sql/001_user_subscriptions.sql
psql < Backend/Supabase/sql/002_user_subscriptions_enhancements.sql

These scripts create public.user_subscriptions, enable RLS, and add helpful indexes.

8.6 Deploy RevenueCat Webhook Function

  1. Install the Supabase CLI and log in.
  2. Deploy Backend/Supabase/edge/user_subscriptions_webhook.ts as an Edge Function:
supabase functions deploy user-subscriptions-webhook \
  --project-ref YOUR_PROJECT_REF \
  --no-verify-jwt

Set the following environment variables for the function:

  • SUPABASE_URL – Your project URL.
  • SUPABASE_SERVICE_ROLE_KEY – Service role key (keep secret, set via dashboard).
  • REVENUECAT_API_KEY – Optional; enables email lookup for webhook payloads.

In RevenueCat, add a webhook pointing to https://<PROJECT_REF>.functions.supabase.co/user-subscriptions-webhook.

8.7 Local Development without Supabase

Set backend = .local in AppConfig.default or override via dependency injection to use mock repositories that keep data in-memory for rapid prototyping.

9. Authentication Flow

Authentication is orchestrated by AuthCoordinator and repositories resolved via DIContainer. Key files:

  • Modules/Auth/AuthCoordinator.swift: Presents sign-in and profile setup flows.
  • Backend/Supabase/SupabaseAuthRepository.swift: Wraps Supabase Auth API.
  • Modules/Auth/CreateAccountView.swift & SignInView.swift: SwiftUI screens.

9.1 Email Sign-Up & Login

  1. User enters email/password; Supabase handles credential storage.
  2. After authentication, ProfileSetupView collects optional profile data.
  3. Profile repository saves metadata to Supabase or local storage depending on the backend.

9.2 Sign in with Apple

The button is present but disabled. To enable:

  • Fill Apple keys inside Secrets.swift.
  • Add Sign in with Apple capability to the Xcode target.
  • Implement the ASAuthorization flow inside AuthCoordinator.

9.3 Handling Auth State

RootView observes auth status with @AppStorage and NotificationCenter updates. When the user logs in, the app:

  1. Calls purchasesService.logIn(userID) to link RevenueCat.
  2. Refreshes entitlements to unlock premium content.

9.4 Removing the Test Drive Screen

The debug-only Test Drive overlay defined in Core/Root/TheSwiftKitApp.swift helps QA preview flows. To remove it:

  • Delete the #if DEBUG block that wraps TestDriveView, or set @State private var showTester = false and remove references.
  • Alternatively, exclude Modules/Demo/TestDriveView.swift from the build target.
  • Ensure release builds do not compile the demo module (remove from target membership).

10. RevenueCat Paywall & Subscriptions

The paywall is powered by Modules/Paywall/PaywallView.swift with offerings sourced from RevenueCat when configured.

10.1 Connect RevenueCat

  1. Create products in App Store Connect that match your entitlement strategy.
  2. In RevenueCat, create a project and sync the App Store products.
  3. Configure an offering with packages (e.g., monthly, yearly).
  4. Copy the iOS public API key into Secrets.revenueCatAPIKey.
  5. Link the webhook (see Supabase section) if you mirror subscriptions in your backend.

10.2 Local Paywall Preview

If the SDK or API key is missing, the app uses NoopPurchasesService and fake offerings defined in code so the UI is still testable.

10.3 Customizing Paywall Content

  • Modify copy and layout in Modules/Paywall/PaywallView.swift.
  • Update the StoreKit configuration (Resources/StoreKit/Paywall.storekit) to simulate StoreKit purchases in Xcode previews.
  • Badges and call-to-actions adapt based on introductory offers automatically.

10.4 Entitlement Handling

Notification.Name.subscriptionDidChange informs RootView about entitlement changes. Hook into this notification to unlock premium content in your modules.

11. TelemetryDeck Analytics

11.1 Setup

  1. Create an app in the TelemetryDeck dashboard.
  2. Copy the App ID into Secrets.telemetryDeckAppID.

The DI container chooses between TelemetryDeck v2, TelemetryClient v1, or a no-op implementation depending on your package dependencies.

11.2 Tracking Signals

  • Use container.analytics.track("Event.Name", properties: [:]) from anywhere in the app.
  • Identify users via analytics.identify(userID:) (implement if required by your analytics provider).

11.3 Debugging

In DEBUG builds, the analytics service logs when it is configured and when signals are sent.

12. Notifications

Notification handling lives in Core/Notifications/NotificationService.swift. The debug UI is Modules/Notifications/NotificationsDebugView.swift.

12.1 Request Permissions

Call await NotificationService.shared.requestAuthorization() or use the debug screen to prompt the system alert.

12.2 Scheduling Local Notifications

Use scheduleLocal(title:body:secondsFromNow:categoryIdentifier:userInfo:) to fire a banner after a delay. Customize title/body for marketing or retention flows.

12.3 Calendar & Repeat Notifications

scheduleCalendar accepts DateComponents for precise scheduling (e.g., every Monday at 8am). Enable repeats via the repeats flag.

12.4 Custom Categories & Actions

Define interactive notifications through registerDefaultCategories(). Replace actions and identifiers to match your business logic.

12.5 Remote (APNs) Setup

  1. In Xcode, enable Push Notifications and Background Modes (Remote notifications).
  2. Upload your APNs key/certificate to your server or messaging provider.
  3. Call NotificationService.shared.registerForRemoteNotifications() once permissions are granted.
  4. The device token is logged and exposed via lastDeviceTokenHex.

12.6 Theming & Assets in Notifications

For rich notifications (images, buttons), add payload attachments on the server side. Customize notification titles and bodies either in the scheduling methods or from your push provider.

12.7 Removing the Debug Screen

To hide NotificationsDebugView in production, remove the route in AppRouter or hide the tab item via feature flags.

13. AI Wrappers & OpenAI Backend

The app communicates with a lightweight Flask server that wraps OpenAI's Chat Completions, Image Generation, and Vision APIs.

13.1 Python Backend Setup

  1. Install dependencies: pip install -r Backend/Python/requirements.txt.
  2. Create Backend/Python/.env with:
OPENAI_API_KEY=sk-...
# Optional overrides
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_CHAT_MODEL=gpt-4o-mini
OPENAI_IMAGE_MODEL=gpt-image-1
OPENAI_VISION_MODEL=gpt-4o-mini
  1. Run locally: python Backend/Python/app.py.
  2. Set Secrets.aiBackendBaseURLString to your backend origin (e.g., http://127.0.0.1:5001).

13.2 Changing Prompts & Commands

  • AI chat prompts live inside the respective SwiftUI view models (e.g., Modules/AI/ if you add custom logic). Update default system messages or conversation starters there.
  • Modify the Flask endpoints to inject guardrails, tool calling, or alternative models.

13.3 Deploying the Backend

Host the Flask server on Render, Railway, Fly.io, or any provider that supports Python & HTTPS. Ensure CORS is configured (already enabled via flask_cors.CORS).

13.4 ATS Exceptions

Info.plist includes exceptions for localhost during development. For production, host the backend on HTTPS and remove temporary ATS exemptions.

14. Local Persistence & Core Data

  • Core/Persistence/CoreDataStack.swift defines an in-memory Core Data stack for demos.
  • Modules/Demo/LocalCoreDataRepository.swift offers CRUD examples.
  • Modules/Demo/LocalDataDemoView.swift renders sample lists using @FetchRequest equivalents.

Replace the model entities or add your own .xcdatamodeld file for real persistence. Update the repository implementation to map your entities.

15. Onboarding Experience

The onboarding coordinator is driven by AppConfig.onboardingStyle and page data in Modules/Onboarding/OnboardingModels.swift.

15.1 Editing Pages

Modify OnboardingPage objects (title, subtitle, system image, background) to match your content. You can load data from JSON or remote config by extending the repository.

15.2 Skipping Onboarding

Disable via featureFlags.onboarding = false or set @AppStorage("hasSeenOnboarding") to true after first launch.

15.3 Custom Entry Points

Wrap onboarding screens inside OnboardingCoordinator or present custom flows by editing RootView.

16. Branding & UI Customization

16.1 Theme Colors

Edit DesignTokens.primaryHex and accentHex (or the Branding struct) to globally change button, gradient, and accent colors.

16.2 App Theme Styles

Core/Theme/Theme.swift defines AppTheme and glass effects. Customize to adjust typography, corner radii, or background treatments.

16.3 Fonts & Typography

Add custom fonts to Resources/, register in Info.plist, and update theme modifiers to apply them.

16.4 Layout Adjustments

Views respond to AppConfig.layout. Extend the enum for list/grid variations or add new layout strategies consumed by feature modules.

16.5 App Name & Bundle ID

  • Display name: update AppConfig.appName and the scheme name in Xcode.
  • Bundle ID: change inside project.yml and re-run tuist generate if you use Tuist (or edit build settings directly).

16.6 Icons & Logo

Replace assets in Resources/Assets.xcassets. Paywall and onboarding look for AppLogo; fallback UI uses app initials if unavailable.

17. Navigation & Flow Control

Navigation is coordinated by AppRouter and RootView.

17.1 Adding Routes

  1. Add a case to AppRoute.
  2. Handle the new case in NavigationStack.navigationDestination.
  3. Push routes using router.push(.yourRoute).

17.2 Modifying Tabs

Edit the TabView in RootView to add or remove tabs. Each tab can wrap its own NavigationStack.

17.3 Conditional Flows

Use FeatureFlags and @AppStorage toggles (e.g., hasSeenOnboarding) to branch flows without rewriting view logic.

17.4 Presenting Modals & Sheets

Paywall uses a .sheet with custom detents. Reuse this pattern for feedback prompts or upsells.

17.5 Removing Demo Screens

Delete demo routes (.aiChat, .notifications, etc.) or guard them with feature flags before shipping.

18. Assets, Localization, & Legal

18.1 Localization

  • Update strings in Resources/Base.lproj/Localizable.strings.
  • Tokens like __APP_NAME__ are replaced at runtime via Localization.swift.
  • Add new language folders (e.g., es.lproj) and duplicate the strings file.

18.2 Legal Links

Set AppConfig.legal.privacyPolicyURL and termsURL to live documents.

18.3 StoreKit Files

Resources/StoreKit/Paywall.storekit and PayWallLocal.storekit help you test paywalls in Xcode. Keep them in sync with your RevenueCat offerings.

19. Debugging & Testing Utilities

19.1 Test Drive View

The debug-only Test Drive interface (Modules/Demo/TestDriveView.swift) lets you:

  • Force onboarding
  • Simulate subscription states
  • Open settings, paywall, or other features rapidly

Remove or hide it before distributing release builds.

19.2 Logging

Core/Logging/Logger.swift centralizes logs. Extend to integrate with services like Sentry.

19.3 Unit & UI Tests

Use the Tests/ directory (currently minimal) to add regression coverage for your features.

20. Build & Deployment Checklist

  • Verify all secrets are set and build configurations exclude sample keys.
  • Disable or remove demo/test screens.
  • Provide production Privacy Policy and Terms URLs.
  • Upload App Store icons and marketing assets.
  • Run through onboarding, auth, paywall, and notification flows on device.
  • Ensure ATS exceptions are removed for release builds if not required.
